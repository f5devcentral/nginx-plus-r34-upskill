## Introduction

NGNIX Plus r34 contains a new native [OpenID Connect](https://openid.net/developers/how-connect-works/) implementation.
The following are supported:

* OpenID Connect **Relying Party**
* OpenID Connect **Client**

This new implementation is intended to replace the 
NGINX Inc [nginx-openid-connect Reference Implementation](https://github.com/nginxinc/nginx-openid-connect) with a native and 
supported solution.

This document discusses the purpose of the feature and provides information for implementors and engineers supporting it.

---

### What does this feature do?

This feature allows NGINX Plus to be used to enforce logon requirements as a web server or proxy in front of a website.
For example, the website or proxy owners may want to enforce a logon from Azure, Okta, Duo, or other OpenID Connect Identity Provider.
Identity Provider (IdP) is sometimes also called **Authorization Server*** (AS).

Because web browsers do not (yet) support OpenID Connect directly, a web site or app must behave as a *proxy* for this access on the 
browser's behalf. Typically the OpenID Connect Client provides an 
[HTTP Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies) to track the browser's session

### What features are missing that may be expected?

The initial implementation of this feature is missing the following items that may limit deployment:

* Proof of Key Code Exchange [PKCE](https://www.rfc-editor.org/rfc/rfc7636.html) support. Administrators must preconfigure a 
Client Secret to bypass this limitation. This type of configuration known as a "private app" or "confidential client", 
as opposed to a "public client" which does not require a pre-shared client secret.
* Logout Support. NGINX's OIDC CLient tracks user sessions with a session cookie There is no mechnaism to terminate or invalidate these user sessions.
* Support for Opaque Tokens. NGINX Plus's OIDC Client relies on **JWKs** to validate incoming JWTs from the AS. It does not support [introspect endpoints](https://www.rfc-editor.org/rfc/rfc7662.html).
* Dynamic JWK updating. **JWKs** are used to validate JWTs. Providers rotate these on a regular basis.
* Session ID Rotation. NGINX Plus's OIDC Client provides a single unchanging session cookie.
